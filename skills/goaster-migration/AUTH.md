# Authentication and authorization

This skill does not grant access or approval. The owner must have a distinct
new BotFather bot configured through GoAsterWeb setup; never ask for or copy a
bot token in the migration conversation. The installed remote agent must be
the root runtime for start, status, stop, and delivery repair. A non-root
runtime must be allowed to reject those actions safely.

The owner is responsible for the correct Hetzner token and project. Do not ask
the model to verify the project. The tool loads `HCLOUD_TOKEN` internally
from the existing localenv store or environment. Never put it, a bot token,
private key, owner URL, callback secret, or chat ID in tool parameters,
prompts, logs, or memory.

The tool itself sends the confirmed handoff only to the already paired private
Telegram user. If protected delivery or the migration scheduler is
unavailable, stop at the tool boundary; do not weaken permissions, use sudo,
or invent a helper.
